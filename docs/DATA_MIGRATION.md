# Перенос данных SQLite (SelAkCRM Nest/Prisma → SelakCRMNew Python)

## Когда подходит «простое копирование»

Если схема таблиц в новой БД **совпадает** с той, что создаётся Prisma в проекте SelAkCRM (имена таблиц в PascalCase, те же колонки), достаточно:

1. Остановить старый и новый API.
2. Скопировать файл базы (например `dev.db`) в каталог нового backend под путём из `DATABASE_URL`.
3. Запустить новый API: при старте выполнится `alembic upgrade head` — **если** ревизии уже применены к этой копии, Alembic не сломает данные. Если версия `alembic_version` отсутствует, выполните вручную из каталога `backend`:

   ```bash
   export DATABASE_URL=sqlite:////абсолютный/путь/к/dev.db
   alembic stamp head
   ```

   Это помечает схему как актуальную без повторного `CREATE TABLE`.

## Если схемы разошлись

1. Экспорт данных из старой БД (SQL dump или скрипт на Python) в нейтральный формат.
2. Импорт в новую БД с маппингом полей.
3. Проверка по матрице приёмки в репозитории SelAkCRM: файл `docs/acceptance-matrix.md`.

## Пароли пользователей

Оба стека используют **bcrypt**. Хэши из старой таблицы `User` переносятся без пересчёта.

## Идентификаторы

Используются строковые id (cuid). Новые записи в Python создаются через ту же библиотеку `cuid`, что сохраняет совместимый формат.
