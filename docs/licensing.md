# Лицензирование SelAkCRM

Полностью офлайн-схема «код запроса → код активации». Клиент никуда не ходит по сети, вендор ничего не публикует.

## Как это работает

1. Вендор выпускает ключ в [License Admin](../license-admin/README.md) и передаёт его клиенту.
2. Клиент вводит ключ в CRM (Настройки → Лицензия) и получает **код запроса**.
3. Вендор вставляет код запроса в админку и получает **код активации**.
4. Клиент вставляет код активации — доступ открыт бессрочно.

## Формат кодов

| Код | Что внутри | Кто проверяет |
|-----|-----------|---------------|
| Ключ `SAK-<id>-<secret>` | Идентификатор и секрет. Секрет только `[A-Za-z0-9]`, без `-`. | Формат — клиент, подлинность — админка по vault |
| Код запроса `SAKREQ-…` | `key_id`, `hwid`, HMAC от секрета ключа | Админка: HMAC доказывает, что у клиента настоящий ключ |
| Код активации `SAKACT-…` | Только подпись Ed25519 над `{key_id, hwid, v}` | Клиент по `public.pem` |

Код активации не содержит полезной нагрузки: клиент знает свой `key_id` и HWID и собирает подписанное сообщение сам. Поэтому код короткий (~90 символов) и действует только на том компьютере, для которого выдан.

Клиент доверяет двум публичным ключам: `backend/selakcrm/licensing/public.pem` и `public_next.pem` — это позволяет менять пару ключей без блокировки установленных копий.

## Лимит устройств

Места считаются **в админке**, в момент выдачи кода. Превысить лимит нельзя: без приватного ключа вендора код активации подделать невозможно, а админка не выдаст код сверх `max_seats`.

- Повторная выдача на тот же HWID место не занимает и возвращает тот же код.
- «Отвязать» освобождает место под другой компьютер.
- Ключ без лимита (`max_seats = null`) разрешает любое число устройств.

## Демо-период

7 суток (`LICENSE_TRIAL_DAYS`) с привязкой к HWID. Маркер дублируется в user-data, ProgramData и HKCU; берётся самая ранняя дата запуска. Перевод часов назад блокирует доступ. После коммерческого ключа демо не возвращается.

## Отзыв: что возможно, а что нет

Отзыв ключа запрещает выдавать по нему **новые** коды. Уже выданные коды бессрочны и проверяются офлайн — удалённо отключить работающий компьютер нельзя. Это осознанный размен: взамен активация не требует сети, публикации реестра и продлений.

## Смена оборудования

HWID считается от `MachineGuid` (Windows), `IOPlatformUUID` (macOS) или `/etc/machine-id` (Linux). Переустановка системы меняет отпечаток: код перестаёт подходить, статус возвращается в «ждёт код активации». Вендору нужно отвязать старое устройство и выдать новый код.

## Клиент (CRM)

Env (см. `backend/.env.example`):

- `LICENSE_TRIAL_DAYS` (7)
- `LICENSE_ENFORCE` — только для dev; в frozen exe гейт всегда включён

API: `/api/v1/license/status|activate|redeem|deactivate`.

`status` отдаёт `requestCode`, когда ключ введён, — отдельный запрос за кодом не нужен.

Сборка Windows exe: CRM — `backend/scripts/build_windows_exe.ps1` → `SelakCRM.exe`; License Admin — `license-admin/scripts/build_windows_exe.ps1` → `SelakCRM-LicenseAdmin.exe` (см. [license-admin/README.md](../license-admin/README.md)).

## Бэкап (обязательно до продаж)

Храните в двух офлайн-местах:

- `license-admin/keys/private.pem` — без него нельзя выдать ни одного кода активации;
- `license-admin/data/` — vault с полными ключами, список выданных ключей и занятых мест.

Потеря приватного ключа означает, что новые активации невозможны, а уже работающие клиенты продолжат работать.

## Ротация ключей подписи

1. Сгенерируйте новую пару.
2. Положите новый public в `public_next.pem`, соберите и раздайте клиентам обновление.
3. Подписывайте новым private.
4. Когда все клиенты обновлены — сделайте новый ключ основным (`public.pem`), очистите `public_next.pem`.
